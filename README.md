# FreeRDPTun 0.1.3

Экспериментальный IPv4 TUN-туннель поверх настоящего Dynamic Virtual Channel
сессии FreeRDP–FreeRDP. Это отдельный проект с новым протоколом и новыми UUID,
не обновление RDPTun 0.4.0 и не его совместимая замена.

## Скачать и начать

Готовые комплекты находятся в
[релизе v0.1.3](https://github.com/mdatto-cell/freerdptun/releases/tag/v0.1.3).
Архивы хранятся в
[packages/v0.1.3](https://github.com/mdatto-cell/freerdptun/tree/main/packages/v0.1.3),
а релиз содержит
прямые ссылки для скачивания: API вложений GitHub отклонил загрузку файлов.
Рабочие конфигурации, UUID, private key и дампы пользователей не публикуются.
Фиксированные UUID в Go-тестах публичны и не предназначены для реального доступа.

- **Новая установка, всё вместе:** `freerdptun-0.1.3-source-and-binaries.zip`
  содержит собственные исходники, закреплённые исходники FreeRDP, Linux/Windows
  сборки с нативными зависимостями, документацию и лицензии.
- **Только сервер/Linux-клиент:** `freerdptun-0.1.3-linux-amd64.tar.gz`.
- **Только Windows-клиент:** `freerdptun-0.1.3-windows-amd64.zip`.
- **Обновление установленного 0.1.0–0.1.2:** `freerdptun-0.1.3-update.zip`;
  это исходный пакет обновления, без native-зависимостей.
- **Проверка файлов:** `SHA256SUMS` в релизе содержит суммы архивов.
  В полных комплектах есть отдельный список сумм файлов внутри.

Для новой установки распакуйте полный или платформенный комплект, затем
прочитайте [инструкцию Linux/Windows](docs/INSTALL_RU.md).
Полное описание параметров: [CONFIGURATION_RU.md](docs/CONFIGURATION_RU.md);
для обновления: [UPDATE_0.1.3_RU.md](docs/UPDATE_0.1.3_RU.md).

Репозиторий содержит исходники приложения и vendored FreeRDP 3.28.0;
готовые файлы хранятся только архивами в `packages/v0.1.3`, не в `dist/`.
Для сборки из клона см. [BUILD_RU.md](docs/BUILD_RU.md).
На сервере требуется Linux x64, целевая ОС Ubuntu 22.04; клиенты Linux x64
и Windows x64. Автоматическая настройка маршрутизации/NAT/DNS отсутствует.

## Изменения 0.1.3

Добавлены управляемые сервером профили `upload`/`download`: padding,
дробление внутри DVC, jitter, исключение малых IP, burst token bucket
и выбор единиц учёта скорости. Политика передаётся клиенту в ответе
UUID-авторизации v2 и защищена HMAC; настройки клиента менять не нужно.

По умолчанию `baseline` не включает модификаторы, но сохраняет действующие
лимиты. Выключатель `rate_limit_enabled` независим от режима. Доступны
настраиваемый keepalive, `POLICY` и периодические/итоговые `STATS`.
Размеры фреймов относятся к нашему потоку DVC, не TCP-сегментам/TLS records.

Порядок обновления: `docs/UPDATE_0.1.3_RU.md`. Полное описание всех полей:
`docs/CONFIGURATION_RU.md`; пресеты: `examples/`.
Сначала обновите сервер, затем клиентов; новый клиент требует сервера 0.1.3.
UUID, сертификат, pin, адреса и native-компоненты сохраняются.

Для 0.1.3 выполнены сборки Linux/Windows и статический анализ. Программы,
тесты, loopback, TUN и нагрузочные проверки по условию пользователя
не запускались. Нативный транспорт остаётся 0.1.0 / FreeRDP 3.28.0.

## Изменения 0.1.2

Сервер и клиенты теперь автоматически назначают интерфейсу адрес из `cidr`
и MTU, Linux также включает link. Windows отключает DHCP только на своём
Wintun и ожидает состояния IPv4 `Preferred`. Default route, DNS, NAT, forwarding
и firewall по-прежнему настраивает пользователь; маршрут подключенной подсети
создаёт сама ОС при назначении IP.

На сервере восстановлен отдельный ранний NLA/CredSSP-отказ для клиентов,
предлагающих HYBRID/HYBRID_EX, включая обычный `mstsc`. Наш FreeRDP-клиент
предлагает TLS-only и продолжает работать через прежний нативный транспорт.
Рабочего стола и проверки системного пароля нет; NTLM challenge не отправляется,
токены и учётные данные не записываются.

Обновление выполняется без замены UUID, JSON, сертификата и pin.
Порядок установки и ограничения: `docs/UPDATE_0.1.2_RU.md`.
Для 0.1.2 выполнялись только компиляция и статический анализ, не запуск
тестов, программ или сетевых соединений. Нативный транспорт остаётся 0.1.0.

## Сохранённое исправление 0.1.1

Исправлена ошибка, при которой неподдерживаемый multicast/broadcast пакет
мог завершить весь сеанс с сообщением `IPv4 source/destination ownership violation`.
Теперь такая нагрузка отбрасывается без разрыва соединения; подмена исходного
адреса клиента по-прежнему завершает сеанс. Журнал содержит адреса пакета
при настоящем нарушении и первые три случая фильтрации.

Порядок обновления без замены UUID, конфигураций и сертификата находится
в `docs/UPDATE_0.1.1_RU.md`. Нативный транспорт остаётся версии 0.1.0;
формат протокола не изменился. Для этого исправления выполнены только
сборка и статический анализ кода: по просьбе пользователя тесты не запускались.

## Что находится в архиве

Полный комплект 0.1.3 содержит файлы ниже. Linux/Windows-пакеты содержат
только свою платформу, документацию и лицензии; исходники доступны в Git
и полном архиве. Нативные файлы сохранены из 0.1.0 без пересборки.

Отдельный update-архив содержит только Go-бинарники, собственные
исходники и документацию. Для него нужны уже установленные `rdpt-bridge`,
DLL/SO и Wintun из полного комплекта 0.1.0 либо 0.1.3.

- **`dist/linux-amd64/`:** готовая консольная программа сервера/клиента, нативный
  `rdpt-bridge` и библиотеки FreeRDP/WinPR, собранные внутри Ubuntu 22.04 x64.
- **`dist/windows-amd64/`:** готовый Windows x64 клиент, `rdpt-bridge.exe`,
  необходимые DLL и оригинальный подписанный Wintun.
- **`docs/INSTALL_RU.md`:** инструкция установки, выдачи нового доступа, запуска
  и диагностики. Сначала прочитайте её.
- **`docs/ARCHITECTURE_RU.md`:** протокол, границы безопасности и ограничения.
- **`docs/CONFIGURATION_RU.md`:** все настройки, диапазоны, примеры и статистика.
- **`examples/`:** серверные объекты-пресеты для слияния с рабочим JSON.
- **`docs/TEST_REPORT_RU.md`:** исторические проверки версии 0.1.0;
  они не являются результатами тестирования версий 0.1.1–0.1.3.
- **`cmd/`, `internal/`, `native/`, `scripts/`:** полный исходный код приложения
  и сценарии сборки; `third_party/FreeRDP/` содержит закреплённые исходники зависимости.
- **`packaging/freerdptun.service`:** пример systemd-службы сервера.
- **`SHA256SUMS`:** контрольные суммы поставляемых исполняемых файлов и DLL.

Перечисленные `dist/` и внутренние `SHA256SUMS` относятся к готовым архивам,
а не к корню Git-репозитория. Контрольные суммы включают и документацию
комплекта; сам файл `SHA256SUMS` из собственного списка исключён.

## Главное отличие от прежнего проекта

Снаружи работает стек FreeRDP: negotiation, TLS, MCS, capabilities, activation,
DRDYNVC и наш прикладной канал `FreeRDPTun::IP::1`. Мы не переключаем TCP-соединение
на самодельные TLS-кадры после стартового X.224-пакета.

FreeRDP предоставляет клиентские и серверные API виртуальных каналов
([клиентские API](https://pub.freerdp.com/api/include_2freerdp_2client_2channels_8h_source.html),
[серверные API](https://pub.freerdp.com/api/libfreerdp_2core_2server_8c.html)).
Использование настоящего стека не является гарантией статистической
неотличимости трафика: TLS не скрывает полностью время и размеры передачи
([RFC 8446, E.3](https://www.rfc-editor.org/rfc/rfc8446#appendix-E.3)).

## Краткий старт

На сервере из каталога `dist/linux-amd64` выполните:

```bash
./freerdptun init-server -dir ./state -server SERVER_IP:3389
./freerdptun check -config ./state/server.json
./freerdptun selftest -config ./state/server.json
sudo ./freerdptun run -config ./state/server.json
```

`init-server` создаёт новый каталог с новым случайным UUID, серверным
сертификатом/ключом и двумя конфигурациями. Передайте клиенту только `client.json`
защищённым способом, а `server.key` оставьте исключительно на сервере.

Клиент Linux: `sudo ./freerdptun run -config ./client.json`.
Клиент Windows: `.\freerdptun.exe run -config .\client.json`
в PowerShell от администратора. Программа создаёт интерфейс, назначает его
адрес и MTU автоматически. Другие маршруты и NAT настраиваются самостоятельно.

## Границы тестовой версии

- **Платформы:** сервер Linux x64, целевая ОС Ubuntu 22.04; клиенты Linux x64
  и Windows 10/11 x64. iOS отсутствует.
- **Аутентификация:** новый секретный UUID на клиента, challenge-response HMAC,
  обязательная проверка SHA-256 сертификата сервера. Клиентские сертификаты не нужны.
- **RDP security:** TLS 1.2 или новее; для VPN NLA/CredSSP отключены,
  авторизация IP-трафика происходит в DVC. Отдельная NLA-ветка всегда отказывает;
  системных пользователей и рабочего стола нет.
- **Несколько клиентов:** один серверный TUN, отдельный RDP-процесс на соединение,
  отдельные IPv4 и очереди, один активный сеанс на UUID.
- **Ограничение скорости:** суммарные и индивидуальные лимиты в бит/с полезной
  IP-нагрузки либо собственных DATA-фреймов; padding учитывается в режиме
  `frame`. Значение `0` означает отсутствие соответствующего лимита.
- **Сетевые изменения:** адрес/link/MTU только своего TUN настраиваются
  автоматически; настройка default route, DNS, IP forwarding, NAT и firewall отсутствует.
- **Не реализовано:** IPv6, автопереподключение, бесшовное возобновление сессии,
  GUI, iOS, desktop, полноценный CredSSP/NTLM/Kerberos-сервер и автоматическая
  калибровка статистического профиля по pcap.

Это тестовая разработка без независимого аудита безопасности. Не считайте
локальные программные проверки подтверждением производительности, устойчивости
к конкретному DPI или совместимости со всеми вариантами сетевого окружения.
